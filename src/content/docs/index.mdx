<Aside type="caution" title="Experimental compiler">
  Zryna is experimental and not production-ready. Exact `--profile data-ownership-v1` activates the
  public M3 owned-data profile with manifest v3. The explicit M2 `control-flow-v1` profile and
  default M1 remain available. Public observations stay scalar; Windows native execution, browser
  bindings, WASI, Components and tracing GC remain unsupported. [Read the authenticated compiler
  status](/reference/compiler-status/) or [run your first M3
  programs](/reference/compiler/next/reference/m3-getting-started/).
</Aside>

## Familiar at the surface, strict underneath

<CardGrid stagger>
  <Card title="JavaScript-friendly syntax" icon="seti:javascript">
    The language is designed to feel natural to JavaScript and TypeScript developers.
  </Card>
  <Card title="Exact types" icon="approve-check">
    Types such as `i32` carry defined width, signedness, and overflow behavior across targets.
  </Card>
  <Card title="One verified IR, three targets" icon="setting">
    The design requires every backend to consume the same verified Universal IR instead of
    translating through another target.
  </Card>
</CardGrid>

```ts title="add.zry"
export function add(left: i32, right: i32): i32 {
  return left + right;
}
```

<Tabs syncKey="target">
  <TabItem label="JavaScript">
    `zryna build` emits a direct ECMAScript module and `zryna run` invokes its exported scalar
    function through strict `i32` carriers.
  </TabItem>
  <TabItem label="WebAssembly">
    The same verified IR emits an import-free core `.wasm` module directly. Browser bindings, WASI,
    and Component Model profiles are not part of the current profiles.
  </TabItem>
  <TabItem label="Native">
    Linux x86-64 builds lower through verified native MIR to a relocatable ELF object; run mode
    links and executes a dynamic ELF binary. Windows and macOS native execution are not claimed.
  </TabItem>
</Tabs>

## The target boundary

The intended source-to-artifact pipeline is:

```text
.zry source
    ↓
replaceable frontend provider
    ↓
strict Zryna semantics
    ↓
verified Universal IR
    ├── JavaScript backend → .js
    ├── WebAssembly backend → .wasm
    └── native MIR → codegen → executable
```
