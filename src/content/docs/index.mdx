<Aside type="caution" title="Foundation stage">
  Zryna is experimental. The repository independently tests a TypeScript 6 executable-syntax reader,
  verified `i32` IR, direct JavaScript emission, native MIR verification, and textual LLVM IR
  emission. There is no WebAssembly backend yet, and these pieces are not connected into a
  source-to-output CLI.
</Aside>

## Familiar at the surface, strict underneath

<CardGrid stagger>
  <Card title="JavaScript-friendly syntax" icon="seti:javascript">
    The language is designed to feel natural to JavaScript and TypeScript developers.
  </Card>
  <Card title="Exact types" icon="approve-check">
    Types such as `i32` carry defined width, signedness, and overflow behavior across targets.
  </Card>
  <Card title="One verified IR, three targets" icon="setting">
    The design requires every backend to consume the same verified Universal IR instead of
    translating through another target.
  </Card>
</CardGrid>

```ts title="add.zry"
export function add(left: i32, right: i32): i32 {
  return left + right;
}
```

<Tabs syncKey="target">
  <TabItem label="JavaScript">
    A library-level proof emits signed 32-bit JavaScript from an already constructed verified IR
    program. The syntax reader is not connected to this backend yet.
  </TabItem>
  <TabItem label="WebAssembly">
    Direct core WebAssembly emission is an M1 deliverable. No WebAssembly backend exists in the
    current foundation, so the website does not present a generated `.wasm` artifact yet.
  </TabItem>
  <TabItem label="Native">
    A separate proof lowers constructed verified IR through native MIR to textual LLVM IR. Object
    emission and executable linking are not implemented yet.
  </TabItem>
</Tabs>

## The target boundary

The intended source-to-artifact pipeline is:

```text
.zry source
    ↓
replaceable frontend provider
    ↓
strict Zryna semantics
    ↓
verified Universal IR
    ├── JavaScript backend → .js
    ├── WebAssembly backend → .wasm
    └── native MIR → codegen → executable
```
